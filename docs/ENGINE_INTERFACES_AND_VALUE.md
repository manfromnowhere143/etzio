# Engine interfaces and paid value

Reviewed October 21, 2026. The native integrity, recovery, storage, isolation,
benchmark and exact target gates retain their existing order.

Etzio should earn its advantage by reducing the work required to reach a correct,
independently checkable decision. More candidate text or more transport adapters
does not establish that advantage. The current executable product is a governed
fixture kernel with a narrow static analyzer. Customer discovery and useful public
engineering contributions can proceed within that capability.

## Questions that should determine the build

What can another reviewer establish from the retained record without trusting the
generator's explanation? Measure correct classification and time to decision, with
failures and incomplete cases mixed into the review set. An unsigned JSON report
is a convenient view; the retained evidence remains the object to check.

Which next investigation would change the decision? The future scheduler should
estimate the information a test could supply and charge the complete cost of
obtaining it. Compare that policy with a simple fixed allocation under the same
budget. Confidence scores and retrospective success labels are insufficient.

Which evidence remains applicable after the target, policy or environment changes?
The future reuse layer needs explicit dependencies and invalidation, with current
authority checked at use. Test against ordinary retrieval and no reuse. A saved
explanation cannot authorize another mission.

Who bears a cost today that this evidence can reduce? The immediate commercial
hypothesis is reviewer effort and integration uncertainty. Measure those costs
with a buyer before committing to a hosted product. Bounty income additionally
requires eligible impact, independent reproduction, program acceptance and payment.

What evidence would make us abandon the proposed advantage? An improvement that
disappears after charging setup, failures, verification and reviewer time does not
justify promotion. Neither does a high score produced by missing outcomes or weak
comparators. Preserve the existing S/F/M/H comparison before separate guidance,
scheduling and reuse experiments; all 18 registration inputs remain unbound.

## Research consequence

[VulContextBench v1](https://arxiv.org/html/2609.32601v1), September 26, examines
retrieved code separately from the code cited in a final security report. Its
111 audited cases come from 307 candidates. Selected methods and results show why
finding relevant context and presenting sufficient evidence should be measured
separately. Gold annotation uses model proposals plus human review; its sufficiency
check uses a model, so it does not establish independent execution or causal impact.
The corpus is selected and wholly positive, limiting any inference about false
reports on benign work. No experiment was reproduced here.

Etzio's inference is to pair evidence sufficiency with legitimate negative cases,
source identity, independent effect checks and reviewer effort. More cited lines
is not itself better evidence. These are proposed evaluation controls, not a new
benchmark admission or a claim of comparative performance.

## Interface decision

| Surface | Decision and concrete trigger |
|---|---|
| CLI | Provide a versioned JSON view of the current fixture scan and accurate failure exits. It supports local integration without deploying a service. |
| Python SDK | Keep current kernel functions internal. Stabilize a small consumer API only after a pilot identifies needed inputs, reports and compatibility obligations. |
| HTTP API | Proposed after a real service consumer, accepted service identity, protected storage, per operation authority, quotas and recovery semantics exist. No listener or deployment is added now. |
| MCP | Proposed as a thin adapter to an already accepted consumer API. A concrete client must need discovery or tool invocation. Tool metadata cannot replace Etzio's authority checks. |

The reviewed [MCP authorization specification, 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)
addresses transport access. Its [tool specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)
warns that annotations are untrusted unless supplied by a trusted server. Etzio
must still enforce mission, target, action, identity and budget at the actual
operation. An access token, connection or `readOnlyHint` is not a TargetContract.
No MCP dependency, credential inheritance or automatic tool execution is added.

## First paid pilot proposal

Offer a bounded reviewability pilot using repository fixtures and synthetic
evidence. Its deliverable is a reproducible local demonstration, a documented JSON
contract, an evidence map and a short assessment of integration and review costs.
The buyer supplies the review workflow and nominates a reviewer. Neither private
customer code nor live infrastructure is needed for this first scope.

Before work becomes an engagement, agree the fee, payment milestone, time cap,
deliverables, license and acceptance criteria. No price, delivery promise or
customer commitment has been made. Existing inquiries to Kusari and OX Security
are demand discovery only.

Proposed acceptance uses completed clean and candidate scans, retained analyzer
failure, parse failure and invalid replay. The reviewer must distinguish all
outcomes without treating absence of candidates as completed analysis. Compare
classification accuracy and reviewer minutes against the buyer's current manual
method, including setup and correction time. Predeclare the smallest useful
improvement with the buyer before measuring. A failed pilot remains a result.

Semgrep and Socket are additional prospects because their public projects expose
concrete problems around scan outcomes and failure evidence. One source review
was posted to each existing pull request: [Semgrep 11973](https://github.com/semgrep/semgrep/pull/11973#issuecomment-6321136314)
and [Socket 1652](https://github.com/SocketDev/socket-patch/pull/1652#issuecomment-6321137464).
These are technical contributions, not commercial solicitations or accepted
engagements. Preserve the original contributors' credit. Wait for relevant replies
before proposing followup work; no automatic reminder or repeated pitch is set.

The bounty lane remains separate. Complete independently administered native
provider qualification, external recovery and writer fencing, protected storage,
independent MARCELLUS/CATO execution, benchmark admission and exact target review.
Only then independently reproduce eligible impact and use the separate submission
approval. A public report, test count or contribution is not a bounty finding or
settled revenue.
